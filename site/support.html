Project support

Get back to a known state.

Start with the plugin guide. For project bugs, include the plugin version, Node version, command name, and a short redacted error.

Read the guideReport an issue

A purchase response was lost

Keep the original journal and its .attempt.json dispatch marker. Recover using that journal against the same marketplace and account. Do not replace its idempotency key or start another purchase to check whether the first succeeded. A timeout or polling error does not establish that no charge happened.

Account, funds, or seller approval

Contact the operator of the marketplace you configured. This project does not operate a default public market, hold every deployment's funds, or approve offers on independently hosted deployments. Never send a wallet seed, private key, or unredacted API key to support.

Report safely

GitHub issues are public. Remove inputs, personal information, endpoint credentials, account identifiers, and journal contents unless a minimal redacted example is necessary. For a suspected vulnerability, use the repository's private vulnerability reporting option if available. If it is unavailable, request a private reporting channel without publishing exploit details or secrets.

Support expectations

Support is provided through the repository with no response-time commitment. Include reproducible steps so maintainers can test the problem. Directory submission, a live operator deployment, and actual paid-service acceptance remain separate readiness steps.
