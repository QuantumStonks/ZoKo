# ZoKo public-directory policy clarification

Status: prepared on 2026-09-29; not sent, submitted, or approved. The user designated XECKZ Inc. and authorized public distribution while retaining all rights. Company verification and final legal terms remain incomplete.

## Evidence and scope

The [current plugin guidelines](https://developers.openai.com/plugins/plugin-guidelines) apply to the universal ChatGPT and Codex directory and restrict commerce to physical goods. They prohibit selling digital services directly or indirectly; they separately allow access to already included subscription features. The [submission documentation](https://developers.openai.com/plugins/deploy/submission) accepts an explicit boolean commerce declaration and description, but that metadata is not policy approval.

ZoKo's requested product charges per typed AI decision. An authorized agent requests a quote and purchases against an existing eCash-funded custodial marketplace balance. The selected seller operates the inference endpoint; its proceeds accrue to the seller's marketplace account after commission. Neither pre-funding nor per-task standing authorization changes the economic nature of these purchases. The plugin supplies no model, public hosted marketplace, default seller, subscription, funds, or claimed production adoption. It bundles local skills and a Node.js CLI/client rather than a hosted MCP app. The package does not perform on-chain withdrawals as a plugin workflow.

This creates a public-listing eligibility conflict requiring authoritative resolution. No provider exception has been granted. Repository publication, private account creation, archive validation, and payment regression tests do not establish directory eligibility.

## Draft for an authorized publisher to send

Subject: ZoKo skills plugin — eligibility of per-decision digital-service purchases

We are preparing ZoKo, with XECKZ Inc. designated as publisher, for the shared ChatGPT and Codex plugin directory. Before submission, we would like clarification of the commerce rule's application to our actual product.

ZoKo lets an agent discover independent sellers, obtain a fixed-price quote for a typed AI decision, and purchase that decision within a user-authorized task and cumulative spending limit. Each purchase debits an existing custodial eCash marketplace balance and credits the seller after commission. Sellers operate their own inference endpoints. This is pay-per-decision digital-service commerce, not physical-goods commerce or access to an existing all-inclusive subscription. The skills-only package bundles a local CLI and client; it has no hosted MCP server or embedded checkout. Our review metadata will declare commerce accurately.

The published plugin guidelines appear to prohibit this offering in the public directory. Is there a documented, currently available eligibility route for this exact model? If not, please confirm that public submission should remain deferred until the policy changes or we explicitly redesign the product. We do not want to disguise transactional behavior as discovery or infer an exception from private installation or successful package validation.

Separately, please identify any applicable public-directory requirements for authenticating a local skills-only CLI through a host-managed environment credential, without requesting or displaying the secret in chat.
